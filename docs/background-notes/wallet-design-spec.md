# NyxForge Wallet Design Specification

> Version 1.0 (April 2026)
> Strategy: Bearer Bounty Management & Key Isolation

---

## 1. The Core Concept

A NyxForge wallet is NOT a traditional crypto wallet that manages on-chain
balances. It is a **Manager of Bearer Instruments**.

### 1.1 The Two Halves of Ownership
Ownership of a NyxForge bounty requires two distinct pieces of data:
1. **The Physical File:** A `.bounty` SQLite archive containing the GoalSpec,
   History, Evidence, and an Encrypted Scalar.
2. **The Private Key:** A local secret key (Ed25519/secp256k1) that can decrypt
    the "Encrypted Scalar" inside the `.bounty` file.

The Wallet's job is to orchestrate these two halves to perform lifecycle
actions (Issue, Transfer, Redeem).

---

## 2. Technical Requirements

### 2.1 Identity Management
- Support for **Monero-derived keys** as the root of identity (BIP-39 or
  Monero seed).
- Generation of curve-specific keys: Ed25519 (XMR), Jubjub (ZEC),
  secp256k1 (BTC/ETH).
- Encryption-at-rest for the key store (passphrase protected).

### 2.2 Bearer File Management
- **Local Sync:** Monitor a "Bounties" directory for new/updated `.bounty` files.
- **Verification:** Automatically verify the Blake3 hash of the GoalSpec and
  the validity of the `lock_txid` on the relevant chain.
- **Redaction:** Ability to export "Public" versions of `.bounty` files (with
  the `scalar_encrypted` field removed) for exchange verification.

### 2.3 On-Chain Integration
- **XMR:** Connect to `monerod` (local or remote) to monitor lock transactions.
- **ETH:** Connect to an RPC provider (Infura/Alchemy) or local `geth`.
- **BTC/ZEC:** Monitor Taproot/Sapling outputs.

## 3. Key Screens & Components

### 3.1 Screen: "The Vault" (Bounty List)
- **State Badges:** DRAFT, ACTIVE, REDEEMABLE, SETTLED, EXPIRED.
- **Bounty Cards:** Compact view showing Title, Amount (e.g., 1.0 XMR), and
  Deadline Countdown.
- **Filtering:** Filter by currency, goal type, or maturity date.

### 3.2 Screen: "Bounty Inspector" (Deep Dive)
- **Goal Tab:** Human-readable description + machine-readable metric.
- **Oracle Tab:** Quorum status, oracle identities, and recent attestations.
- **Evidence Tab:** Gallery of attached BLOBs (PDFs, Videos, JSON).
- **History Tab:** Audit log of all state transitions.

### 3.3 Screen: "The Wizard" (Creation)
- Multi-step flow for Goal -> Timing -> Collateral -> Oracles.
- Interactive "Goal Assistant" (powered by MCP server).
- Preview of the physical `.bounty` file before it is written.

### 3.4 Screen: "Exchange Hub" (Trading)
- **My Listings:** Active listing records generated by the wallet.
- **Transfer Widget:** Input for Buyer's Pubkey + Re-encryption action.
- **Listing Generator:** Produces the JSON Listing Record for copy-pasting.

---

## 4. Security Mandates

1. **Key Isolation:** The raw private key MUST NEVER be written into the
   `.bounty` file.
2. **Scalar Privacy:** The decrypted `s_met` scalar MUST only exist in RAM
   briefly during transfer or redemption.
3. **Redundancy:** Remind users that deleting a `.bounty` file is equivalent to
   burning a physical banknote. The Wallet should encourage "Vault Backups."

---

## 5. Implementation Path

- **Backend (nyxforge-bounty):** Implement the key derivation and re-encryption
  logic.
- **UI (Flutter):** Create the "Vault" and "Wizard" widgets using the
  Widgetbook pipeline.
- **Mock (Mockoon):** Add wallet-specific RPCs (`wallet.list_keys`,
  `bounty.reencrypt`, etc.).
